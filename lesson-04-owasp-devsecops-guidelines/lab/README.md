# Lab: OWASP DevSecOps Guidelines

Hands-on exercise for threat modeling and DevSecOps maturity assessment using OWASP frameworks.

## What You'll Learn

- How to conduct a STRIDE threat model for a real application
- How to assess your organization's DevSecOps maturity
- How to prioritize security improvements based on risk

## Lab Materials

| File | Purpose |
|------|---------|
| `stride-threat-model-template.md` | Blank STRIDE template for your projects |
| `sample-threat-model-webapp.md` | Completed example for an e-commerce app |
| `devsecops-maturity-checklist.md` | Self-assessment across 6 security dimensions |

## Exercises

### 1. Review the sample threat model

Read `sample-threat-model-webapp.md` to understand how a completed threat model looks. Note how threats are categorized, rated, and tracked to mitigations.

### 2. Create your own threat model

Copy `stride-threat-model-template.md` and fill it in for an application you work on. Aim for at least 3 threats per STRIDE category.

### 3. Assess your DevSecOps maturity

Work through `devsecops-maturity-checklist.md` honestly. Identify your current level in each dimension and set realistic target levels.

### 4. Prioritize improvements

Based on your maturity assessment, identify the top 3 actions that would have the highest security impact for the lowest effort.

## Key Takeaways

- Threat modeling is most effective when done early and revisited regularly
- STRIDE provides a systematic framework that prevents blind spots
- Maturity assessment helps prioritize security investment
- Not all threats need immediate mitigation - risk acceptance is valid when documented
